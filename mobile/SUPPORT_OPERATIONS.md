# 問い合わせ運用メモ

このメモは、グッとれの問い合わせを運営側で確認・対応するための手順です。
ユーザー向けアプリには管理画面を入れず、当面は販売/審査用 Supabase project の `support_requests` を運営側だけが確認します。

## 基本方針

- 問い合わせには受付番号を付け、アプリ画面でユーザーに表示します。
- 返信が必要な場合は、`support_requests.email` の登録メールアドレスへ返信します。
- パスワード、認証コード、住所など、不要な個人情報は聞きません。
- X ID、画像、取引メモなどの個人情報に近い内容は、必要最小限だけ確認します。
- 取引相手とのトラブル、配送、支払い、返金、真贋などは、当事者間での解決を案内します。

## カテゴリ

アプリから送られるカテゴリは `metadata.category` に保存されます。

| category | 表示名 | 対応方針 |
| --- | --- | --- |
| `bug` | 不具合 | 再現条件、端末、発生画面、操作手順を確認します。保存・削除・個人情報表示の不具合は優先します。 |
| `howto` | 使い方 | 操作案内で解決できるものは返信します。ヘルプ化できそうな内容は改善候補にします。 |
| `request` | リクエスト | すぐ対応できなくても、改善候補として残します。要望が多いものは優先度を上げます。 |
| `account` | アカウント・データ | ログイン、データ削除、課金、個人情報に関わるため優先して確認します。 |
| `other` | その他 | 内容を見て、上のカテゴリに準じて対応します。 |

## ステータス

`support_requests.status` は次の3つで運用します。

| status | 意味 | 使うタイミング |
| --- | --- | --- |
| `open` | 未対応 | 新しく届いた状態です。まずここを確認します。 |
| `in_progress` | 対応中 | 調査中、返信待ち、実装修正待ちの状態です。 |
| `closed` | 対応済み | 返信済み、修正済み、対応不要判断済みの状態です。 |

将来、問い合わせ量が増えたら `waiting_user` や `resolved` を追加します。今は3つに絞ったほうが運用しやすいです。

## 優先度の目安

優先度はテーブルの列には持たせず、まずは運用判断にします。

| 優先度 | 内容 |
| --- | --- |
| 高 | 他人のデータが見える、画像が漏れる、削除できない、ログインできない、保存データが消えた |
| 中 | 保存できない、画像が表示されない、主要操作ができない、アカウント・課金相談 |
| 低 | 使い方質問、表示改善、機能リクエスト、文言修正 |

個人情報やデータ消失に関わるものは、迷ったら高めに扱います。

## 確認手順

1. Supabase Dashboard で販売/審査用 project を開きます。
2. `Table Editor` で `support_requests` を開きます。
3. `created_at` の新しい順に並べます。
4. `status = open` の問い合わせから確認します。
5. 対応を始めたら `status` を `in_progress` にします。
6. 返信や対応が終わったら `status` を `closed` にします。

SQL Editor を使う場合は [SUPPORT_OPERATIONS_QUERIES.sql](./SUPPORT_OPERATIONS_QUERIES.sql) の確認SQLを使います。

問い合わせ到着時のメール通知を使う場合は [SUPPORT_NOTIFICATION_SETUP.md](./SUPPORT_NOTIFICATION_SETUP.md) を設定します。

## 返信テンプレート

### 不具合

件名例: `【グッとれ】お問い合わせ受付番号 XXXXXXXX について`

本文例:

```text
グッとれサポートです。
お問い合わせありがとうございます。

いただいた不具合内容を確認しています。
再現確認のため、必要に応じて追加で状況を伺う場合があります。

受付番号: XXXXXXXX
```

### 使い方

```text
グッとれサポートです。
お問い合わせありがとうございます。

いただいた内容を確認し、操作方法についてご案内します。
画面名や操作手順が分かると、より正確に確認できます。

受付番号: XXXXXXXX
```

### リクエスト

```text
グッとれサポートです。
機能リクエストをありがとうございます。

いただいた内容は今後の改善候補として確認します。
すべてのご要望に個別対応をお約束するものではありませんが、利用状況や要望数を見ながら検討します。

受付番号: XXXXXXXX
```

### アカウント・データ

```text
グッとれサポートです。
お問い合わせありがとうございます。

アカウント・データに関する内容として確認します。
本人確認や追加確認が必要な場合は、このメールアドレス宛にご連絡します。

受付番号: XXXXXXXX
```

## 次に自動化すること

- 問い合わせ受付時のメール通知と自動返信: [SUPPORT_NOTIFICATION_SETUP.md](./SUPPORT_NOTIFICATION_SETUP.md)
- `status` 変更時の対応メモ保存
- アカウント本体削除を行う Supabase Edge Function
- 管理者だけが見られるサポート管理画面
